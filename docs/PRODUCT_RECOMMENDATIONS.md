# Product recommendations

This roadmap reflects the current working implementation. It separates user-facing improvements from the real-device and educator reviews that still require people and equipment outside the codebase.

## Current working baseline

- A first-session choice on Home that routes beginners to a short kit tour, touch/keyboard pads, or an electronic-kit pattern; the electronic-kit path opens Trainer input setup and timing correction.
- Guided lesson notes, saved practice checkpoints, and an editable daily plan informed by local Trainer and Song Library history.
- The Home practice plan supports five-, twelve-, and twenty-minute sessions. It sequences a pulse warm-up, a learner-specific focus pattern, a selectable fresh reading/listening/creative task, and a musical application; plans resume as timed guided sessions. Time and transfer-area preferences, like Home shortcuts, are saved locally per learner profile. Progress shows activity across lessons, timing, reading, listening, improvisation, and songs with each scoring system kept separate; Song Library evidence follows the active learner profile, while song charts remain shared. Learners can set a local weekly target for practice days, lesson completions, or focused sessions.
- Home promotes due Song Library sections for the active learner, older completed lesson skills without later follow-up practice, and consistently low recent reliable Trainer rounds in a cross-mode review queue. The highest-priority review becomes the Home recommendation.
- Progress transfers include a paused guided session and the active profile's weekly goal. Import review lets learners choose whether those items replace the active profile's copies; practice progress still merges.
- The backup panel identifies active-profile Song Library practice history, notes, and recordings alongside shared song charts and device-wide custom grooves, Trainer takes, backing tracks, and custom samples.
- New Practice Pad and Trainer activity dates and weekly targets use the learner's local calendar. Lesson completion timestamps are retained for weekly lesson goals and included in web progress-transfer exports.
- Full local backup and restore for settings, progress, songs, grooves, samples, and saved takes.
- A per-device timing calibration flow and input confidence feedback for MIDI and audio, plus an optional local repeatability log for comparing three calibration runs.
- An opt-in offline download for the main learning and practice pages, built-in sounds, and the production app shell.
- Shared-device learner profiles for lesson progress and Trainer history, plus exact lesson/pattern assignments, score-based completion evidence, assignment-pack import/export, roster CSV export, and private account roster sync with review and revision checks.
- A classroom overview with assignment status, overdue work, recent scored accuracy, and last-practice date. Learners or guardians can explicitly export a compact progress report for import on another device; imported reports remain local, can complete matching assignments, and exclude recordings.
- Original synthesized play-along loops with rock, funk, and shuffle feels; six editable original starter forms; plus up to six imported local stems with shared tempo sync, per-stem downbeat and volume, and user-entered source/rights notes. Users can export or import a portable package containing the active form, mix settings, stems, and attribution. The app does not verify rights. [Play-Along audio](PLAY_ALONG_AUDIO.md) describes limits and release checks.
- The local audio manager includes Song Library recordings, Trainer takes, and Song Builder/Play-Along backing audio with size display, original-file export, and confirmed deletion. Audio remains independent of the offline page cache.
- Optional private progress sync with revision review and recovery, separate from local recordings and Song Library sharing.
- Trainer variations for seated/no-kick practice and one-voice/reduced-reach practice on web and iOS, with a reviewable, export-gated, deletable local player/educator feedback log. Adapted results are excluded from full-pattern mastery comparisons; educator validation is still needed.
- Device calibration trials have local export review and deletion controls. Real-device results are not signed off until a human completes the physical-device matrix.
- A local calibration-log summarizer groups exported trials by browser, platform, input profile, setup, and output while omitting user-entered setup labels from its summary. It reports repeatability spread for three-trial batches without presenting a hardware accuracy claim.
- Classroom report export has learner/guardian permission, report removal, and profile deletion controls; [classroom report policy](CLASSROOM_DATA_POLICY.md) describes the included fields and limits.
- Offline download version notice and storage estimate. Updates stage into a unique cache and switch only after the assets and pages finish; failed or low-storage updates remove the incomplete copy and preserve the last complete download, including when retrying the same build. Physical storage-pressure validation remains open.
- Offline build checks keep the generated route manifest aligned with the service worker route allowlist, and disconnected guided-session launch uses a cached document navigation. Production browser navigation, interrupted-update, and storage-pressure checks remain open.
- Song Library discovery by BPM range, voice, subdivision, feel, and fills; rule-based smart collections; 15 original catalog songs; 10 guided learning paths with style, meter, skill, difficulty, and prerequisite metadata; local reference-audio attachments with pitch-preserving speed control; MIDI exchange; practice-only groove variations; configurable limb isolation; setlist readiness summaries; shared arrangement comments; local drummer usability feedback; full eight-voice song-session scoring; per-voice progress evidence; and field/section-level cloud conflict resolution.
- Song Library follow-up improvements add progress-aware smart collections, cross-ID duplicate candidates during import, local A/B audition for arrangement snapshots, setlist offline preflight, and a local health report for storage, attachments, and backup age. These checks run on the current device; external reference links still need connectivity and audio remains local.
- Song Library performance improvements include full-song score printing, a repertoire-wide skill map, resumable live setlist runs with local outcomes, selective snapshot recovery down to a bar, and reusable kit/MIDI profiles with setlist compatibility checks. Standard MIDI exchange was already available in the Arrangement workspace.
- Song Library planning now includes dated per-song goals tied to arrangement-specific scored passes, a repertoire upkeep queue for due or inactive songs, and learner assignments that check the selected song part against tempo, accuracy, and round requirements. The web and iOS libraries exchange reviewed multi-song packs with duplicate choices and explicit iOS voice compatibility warnings. Shared-snapshot comment threads support replies and owner/editor resolution.
- Recent Song Library improvements add visible task-based starting points, non-blocking arrangement and source checks, web-to-iOS voice compatibility guidance, input/tempo caveats in score comparisons, separate self-rating evidence, setlist debriefs that create passage-specific practice queues and next-day reminders, progressive disclosure in the arrangement workspace, accessible grid controls, and structured local usability observations with task time, test surface, input setup, and drummer experience. The form records anonymous observations only after the drummer agrees. Real-player and device validation still needs to be completed.
- Song Library now puts staff/tab notation first in Overview and Practice, with the step grid collapsed until an editor opens it. Original catalog entries support human educator review records that become stale when arrangement or reviewed song metadata changes; the recorded reviewer assertion is not credential verification. Three new original multi-section pieces add scored paths for song transitions, triplet turnarounds, and syncopation-to-fill coordination. MIDI exchange, synchronized local reference audio, local onset review, learner assignments, and snapshot comparisons were already available and remain part of the same workflows.
- Native iOS includes an offline Song Library, locally saved personal song projects, single-song JSON and reviewed multi-song transfer packs shared with the web Song Library, and version 2 local progress backups containing personal songs. Version 1 backups remain readable and preserve songs already on the device. The Trainer accepts Core MIDI drum notes and one-voice microphone input, with editable MIDI note mapping, local room-noise sensitivity calibration, and a saved timing correction per input. Microphone scoring detects level changes and does not record audio; real-device accuracy checks remain open.
- Web and iOS can exchange a reviewed progress-transfer JSON containing shared lesson completions, up to 50 scored practice summaries, best scores, and preferred tempo. Import merges progress; web preserves unfamiliar pattern IDs as history labels, while iOS reports and skips IDs outside its bundled curriculum. Full recovery backups and account sync remain platform-specific; [cross-platform transfer](CROSS_PLATFORM_TRANSFER.md) documents the scope and release checks.
- A global `Ctrl/⌘ K` launcher for routes, lessons, built-in grooves, rudiments, saved songs, and direct Song Library searches; a flexible curriculum map that links to lesson checkpoints; and silent, step-through visual technique demonstrations in each lesson.
- Trainer random cues now keep their selected spacing across the entire round, including repeated single-bar grooves. Round recaps include an optional per-bar timing and dynamics table, and the groove catalog can filter by style, meter, playable tempo range, and practice focus.
- Scored recaps can start a one-minute drill focused on the weakest instrument and beat. Trainer cues include voice dropouts and accent shifts, and device readiness summarizes recent audio input quality by selected profile.
- A permission-gated JSON timing diagnostics report with browser capabilities and aggregate timing metrics. It excludes audio, device identifiers, hit-level records, and personal notes.
- Reviewed translations for newer page introductions and selected navigation, curriculum, demo, backing-audio, feedback, and diagnostic controls in English, Spanish, French, German, and Brazilian Portuguese. Draft translations now also cover the guided Trainer entry, skill-path checkpoints, custom song-form controls, and score explanations in those four non-English locales. Other supported locales use English fallback for this newer web copy. Native Song Library labels have string-catalog entries for all 24 locales. The [localization and accessibility audit](LOCALIZATION_ACCESSIBILITY_AUDIT.md) has not yet been signed off by human reviewers.
- A local UI localization audit reports untranslated/source-equal literal strings and placeholder mismatches across the app catalogs and app-copy fallbacks. Dynamic translation keys and human translation or accessibility quality are still outside that scan.

## Next priorities

1. **Validate timing on real devices.** Run the calibration and scoring matrix in [device validation](DEVICE_VALIDATION.md) across iOS Safari, Android Chrome, desktop browsers, MIDI, and audio inputs. The local trial log helps compare repeatability; it is not proof of device accuracy.
2. **Review authored play-along audio exchange.** Six original starter forms now work with the portable package, which carries the active form, audio, mix settings, and attribution together. Ask musicians and educators to review the workflow and rights notes using the [content review sheet](CONTENT_REVIEW.md), then curate shareable authored stem sets with clear licensing.
3. **Review adaptive practice and Song Library workflows with drummers.** Use the local feedback forms to collect observations about clarity, movement, song discovery, notation, editing, setlist preparation, and access needs. Then review those observations with players and educators before treating the workflows as validated. See [adaptive practice](ADAPTIVE_PRACTICE.md).
4. **Validate offline upgrades in production browsers.** Use the [offline release checklist](OFFLINE_VALIDATION.md) to confirm route refresh, internal navigation, storage pressure, and update recovery while preserving progress on Safari, Chromium, and installed iOS PWAs. The in-app version notice does not replace a device matrix.
5. **Validate native iOS input and backups.** MIDI/audio setup, input-specific correction, and personal-song progress backups are implemented. Run the physical-device matrix for USB and Bluetooth MIDI, microphone permission and noise calibration, route changes, backup restore, and five-voice interchange on iOS and web. Microphone input currently scores one selected voice at a time; it does not classify a full kit from one microphone.
6. **Expand classroom reporting carefully.** Named learner reports now support explicit file-based sharing across devices with a learner/guardian permission step and local removal. If adding account-based class groups, define teacher ownership, learner consent, retention, and revocation before syncing any report data.
7. **Complete the localization and accessibility audit.** New guided-session, cross-mode progress, weekly-goal, Home review-queue, learner-data-scope, and selected Trainer flows have draft translations in Spanish, French, German, and Brazilian Portuguese. Review those flows with fluent speakers, then review interactive Trainer, Kit Guide, dialogs, storage and error states, RTL layouts, screen readers, keyboard focus, text scaling, and Play-Along workflows. Use [the manual audit matrix](LOCALIZATION_ACCESSIBILITY_AUDIT.md); do not mark translated strings as accepted without a fluent reviewer.

## Product constraints

- Practice recordings, reference audio, and audio input stay on the device unless the learner exports a file. Progress sync is explicit and never includes audio recordings.
- iOS microphone scoring processes short audio buffers for level changes only; it never records or saves audio and currently scores one selected voice at a time.
- Imported play-along backing audio stays in local browser storage. It is independent of the downloadable offline page cache and is not removed when that cache is cleared.
- Timing scores describe a measured input profile; results should not be compared across different browsers, input routes, or hardware without a fresh calibration.
- Play-along audio must have documented rights and clear attribution. Imported backing audio remains local; synthesized loops are original app output.
- Adaptations are optional practice variations, not medical or ergonomic advice.

## Song Library follow-up delivered

- Web transfer packs can include selected songs or a collection and split the selection into numbered files that fit the iOS count and size limits. Unsupported voices can be mapped in a preview, with collision counts, into separate compatible song copies while preserving each source arrangement.
- The Overview includes a library-wide open-goal dashboard and a time-budgeted practice queue that responds to current arrangement matches, scored outcomes, missed voices, due reviews, schedules, and incomplete goals.
- Shared-snapshot comments can carry a structured hit-change proposal at a part-grid step. Owners and editors review the visible diff; applying a current-revision proposal updates or creates a local shared copy after confirmation.
- Guided song paths now include ten prebuilt progressions, style/meter/skill/difficulty filters, prerequisites, and the same metadata for custom paths. The catalog uses original Drum Hero practice songs; educator review remains a product validation step and is not claimed as completed.
