# Initial skill assessment

Open **Initial skill assessment** from Home or Progress, or search for it in the web launcher. The optional assessment runs on web and iOS without an account, recording audio, or requesting microphone access. A typical first pass takes about five minutes; setup, replays and retries add time.

## Flow and scoring

Choose keyboard, touch or MIDI, and a full-kit, hands-only or single-voice path. Single-voice is intended to provide a one-hand-friendly path using one pad; hands-only replaces kick targets with tom. Notation-led mode is the default. Audio-only questions keep notation visible during playing but replace notation quiz items. The optional screen-reader-first rhythm mode replaces the staff with a speech-friendly bar-by-bar text guide and uses listening questions; reading is reported as untested. These paths are labeled in results and kept separate for comparisons. Enable audio and make an unscored hit before beginning. Trainer provides mapping and timing calibration; the assessment reuses those saved corrections and records whether the selected input profile had been calibrated. Uncalibrated timing is called out in measurement-quality notes and prevents comparisons across mismatched calibration states or corrections. Native keyboard uses the existing touch/keyboard timing correction. Native MIDI corrections are stored per Core MIDI source ID, with the former shared correction as the initial fallback.

Content revision 7 in `shared/assessment-v1.json` defines three tiers each for pulse, subdivisions and coordination, an optional MIDI dynamics probe, an optional fresh-groove transfer check, an optional internal-pulse check, and an optional tempo range check. The question bank contains 12 listening and 12 notation questions; notation-led mode selects two listening and three notation items, prioritizing one notation item from each of pulse, subdivisions, and coordination when available. If a notation answer conflicts with the played tier for that area, the assessment may add one unseen notation follow-up for that area. Reading feedback reports correct, answered and available counts by rhythm area; single-item evidence is explicitly labeled provisional, and skipped questions are not treated as wrong. Audio-only and screen-reader-first modes use four listening items. Each result pins its selected question IDs, including any conditional follow-up, and choices are shuffled without changing answer IDs. The expanded bank reduces repeat exposure, but items still need educator review. Core tiers within each skill domain use the same 72 BPM so increasing tempo does not masquerade as increasing complexity. The optional tempo check holds the quarter-note pattern constant and steps through 60, 72, 84 and 90 BPM; the highest passing tempo is reported separately and never changes skill tiers. A score of at least 95 with timing error at or below 40 ms on tier 1 skips the middle probe and moves to the challenge; if both challenge attempts fail, the middle tier is offered as a fallback. The skipped tier remains explicitly untested. The fresh-pattern check uses an alternate groove; it is reported separately and never adds a demonstrated tier. Learners can record a fresh-pattern baseline before practice and return after practicing for one follow-up on a different pattern form; local timestamps, comparable scored Trainer rounds, estimated session minutes, and optional outside-app practice minutes describe the interval. This exploratory comparison does not change placement. Anonymous educator exports include elapsed time and practice context, not absolute timestamps. The internal-pulse check plays the metronome for two bars and then drops it for two bars; it reports matched timing and drift without changing a tier. Every scored playing probe displays a four-bar drum score by default, demonstrates one bar, counts four beats, and measures four bars. Only metronome clicks play during the measured phrase, except during the optional dropout check. Assessment input does not add ordinary practice sessions, personal bests or lesson completions. Saved result records stay at format version 1 and also record the shared content revision and selected access options. New fields are optional so older results and backups remain readable; legacy results with no revision are excluded from revision-to-revision comparisons and exported as unknown.

Advance a tier with a score of at least 85 and mean absolute matched-hit error no greater than 60 ms. Existing Great/Good matching windows and extra-hit penalties apply. A failed tier permits one retry; a second failure ends that domain. Skipping ends the current domain without treating higher tiers as failures. Stopping early retains only completed tasks.

Hands-only moves kick targets to tom to keep simultaneous voices distinct. Single-voice omits coordination. Keyboard/touch voice coordination is not evidence of physical limb independence. Adapted results carry their path label and are not compared with full-kit results.

MIDI dynamics measures alternating soft/accented snare strokes, requiring at least 80% matched targets and median accented velocity at least 20 above median soft velocity. At least two velocities in each target class are required; missing or constant velocity reports **Unmeasured**. Native MIDI preserves decoded velocity through an additive callback; existing MIDI clients retain their original callback.

Learners select a goal (balanced foundation, playing with others, reading notation or expressive playing) and a visual or audio-only question format. Notation-led mode remains the default. New assessments prioritize unseen questions; choices are shuffled, audio can be replayed, and answers appear in results. Learners can optionally report whether each assessed skill felt easy, about right, hard, or affected by input trouble. This feedback is saved separately and never changes scores or tiers. Larger notation, slower demonstrations, an eight-beat count-in, larger touch targets, optional spoken or haptic count-ins, and the screen-reader-first rhythm guide can be enabled before starting. The active access choices are saved with the assessment and shown in anonymous educator review; progress comparisons require the same setup. Setup guides learners through each required voice, plays its preview, and requires them to confirm the expected sounds match the labels before beginning; MIDI mapping can be reviewed before the check. MIDI setup also reports observed velocity range. Single-voice mode is described as one-hand friendly: it checks pulse and subdivisions on one voice and omits coordination; it does not imply physical independence. Results describe evidence confidence as not tested, limited, tentative or supported; this is an explanatory guide, not a statistical guarantee. Measurement-quality notes call out incomplete coverage, low hit matching, cutoff-near results, retries, and large saved timing corrections. Close scores can be checked with one alternate pattern; this evidence remains separate and never changes tier placement. Focused practice tips use misses, extra hits, timing spread and early/late bias. The result labels its 60-second notated prescription as an assessment-phrase example and names the curriculum pattern opened by **Practice this skill**, since those patterns may differ. Retry probes use a second versioned pattern where the skill allows an equivalent variation. Learners can return for the fresh-pattern check; retakes compare transfer, tempo and internal-pulse results when both are available. The bank and thresholds remain product defaults pending educator validation; they are not standardized placement norms. See [the educator pilot guide](ASSESSMENT_PILOT.md), which includes a proposed multi-phase validation study protocol.

Backgrounding, input disconnection and audio interruptions discard the active probe without saving partial evidence. Completed tasks are checkpointed by web learner profile and on native device for 14 days; resume starts the interrupted task with a fresh demonstration and count-in. Completing or retaking clears the checkpoint. Changing the web learner resets the flow and loads only that learner's checkpoint. Input selection stays fixed within an assessment.

## Results and practice

Results show demonstrated tiers, a coverage-aware reading estimate by pulse, subdivisions and coordination, matched percentage, score, misses, extras, mean absolute timing error, early/late bias, timing spread, dynamics availability, quiz feedback and untested tasks. Audio-only and screen-reader-first results mark reading as untested; notation areas with one available item are labeled provisional. Comparable history requires the same question format, input, adaptation, calibration and access options. Recommendations follow the earliest observed unmet prerequisite and explain the evidence with a measurable next goal; omitted domains are not assigned invented scores. With no completed tasks, **Use this starting plan** is unavailable. Optional educator mode collects independent skill estimates before the learner starts, then offers fields for recommendation fit and disagreement notes after results appear. An optional teacher-assigned random code can link anonymous retakes; it must not contain identifying information. Exports omit the learner name, result date, absolute transfer-check timestamps and MIDI device ID. The offline pilot summarizer groups by content revision, input, adaptation and access options; reports educator agreement, learner input-issue feedback, retake consistency, item-level answer patterns and practice-context summaries with sample sizes and descriptive Wilson intervals.

Applying a result changes Home's suggested lesson and daily focus without completing lessons. Curriculum-matched practice targets are included in the shared content. Newer, reliable Trainer evidence on the same input profile, adaptation, and timing setup takes precedence for daily focus after at least two scored rounds; focus uses up to the five latest rounds per pattern. Older native rounds missing input or timing-setup metadata needed for comparison are excluded. Retaking leaves the applied plan intact until a result is explicitly applied.

The **Practice this skill** link carries only the random assessment record ID, then reads the result from the active learner's local storage. Web and native results both require three consecutive reliable scored rounds on the recommended pattern with at least 85 score, 85% matched hits, and mean absolute timing error no greater than 60 ms, using the same input profile and adaptation. Native Trainer now stores the aggregate timing error needed for this recheck; older rounds without timing evidence do not count. This is practice feedback, not a replacement placement score. Retaking still does not change the applied plan until the learner applies the new result.

Web results are stored under the learner-scoped `drum-hero:assessment:v1` key and resume checkpoints under `drum-hero:assessment-draft:v1`. Native results use `drumHero.assessment.v1` and checkpoints use `drumHero.assessment.draft.v1`. Retain at most 20 completed records; when necessary, preserve the explicitly applied baseline and the newest 19 retakes. History supports review, deletion and stopping use of the plan. Deleting the applied result removes its plan reference. Native MIDI corrections are saved per Core MIDI source ID, with the previous shared MIDI correction used as the initial fallback for uncalibrated sources.

Web full backups already carry learner-scoped app settings, including assessments. Native v2 backups add an optional assessment field; older backups without it preserve the current assessment history. Native Trainer records add optional input/adaptation comparison metadata. Tempo results and educator comparisons are optional fields, preserving compatibility with older assessment records. Cloud sync and web/native backup conversion are not provided for assessment results.

The web `/assessment` route is included in the offline resource manifest; refresh an existing offline download after deployment. Native content and sounds are bundled. New web copy uses the existing translation fallback and native copy follows SwiftUI localization conventions; translations of all new assessment copy still require language review.

## Verification and remaining device work

`shared/assessment-fixtures-v1.json` pins identical TypeScript/Swift scoring cases for timing boundaries, missing/extra hits, negative offsets and velocity contrast. Unit tests cover advancement, skips, validation, recommendations, history retention and backup compatibility. Browser tests cover desktop/mobile layouts, accessibility, keyboard scoring, MIDI loss, profile isolation, applying a plan and interruptions. Native tests cover scoring parity, backup compatibility and simulator assessment flows.

Before a hardware release, manually check USB/Bluetooth MIDI on physical web/iOS devices, saved timing corrections, varied versus constant MIDI velocity, audio route interruptions, external keyboards, VoiceOver and screen-reader timing cues. Check iPhone/iPad layouts with larger text. Simulator and synthetic MIDI checks do not establish physical device latency or educator validity.
