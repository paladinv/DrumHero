# Initial skill assessment

Open **Initial skill assessment** from Home or Progress, or search for it in the web launcher. The optional assessment runs on web and iOS without an account, recording audio, or requesting microphone access. A typical first pass takes about five minutes; setup, replays and retries add time.

## Flow and scoring

Choose keyboard, touch or MIDI, and a full-kit, hands-only or single-voice path. Single-voice is intended to provide a one-hand-friendly path using one pad; hands-only replaces kick targets with tom. A larger-notation preference supports reading during the flow, and audio-only quiz format offers a listening-led alternative. These paths are labeled in results and are kept separate for comparisons. Enable audio and make an unscored hit before beginning. Trainer provides mapping and timing calibration; the assessment reuses those saved corrections and records whether the selected input profile had been calibrated. Uncalibrated timing is called out in measurement-quality notes and prevents comparisons across mismatched calibration states or corrections. Native keyboard uses the existing touch/keyboard timing correction. Native MIDI corrections are stored per Core MIDI source ID, with the former shared correction as the initial fallback.

Content revision 7 in `shared/assessment-v1.json` defines three tiers each for pulse, subdivisions and coordination, an optional MIDI dynamics probe, an optional fresh-groove transfer check, an optional internal-pulse check, and an optional tempo range check. The question bank contains 12 listening and 12 notation questions; visual mode selects two listening and three notation items, while audio-only mode keeps four listening items. Each result pins its stable randomized subset, and choices are shuffled without changing answer IDs. The larger bank reduces repeat exposure, but the new items still need educator review. Reading feedback maps the completed notation subset to three broad levels; skipped questions leave reading unmeasured. Core tiers within each skill domain use the same 72 BPM so increasing tempo does not masquerade as increasing complexity. The optional tempo check holds the quarter-note pattern constant and steps through 60, 72, 84 and 90 BPM; the highest passing tempo is reported separately and never changes skill tiers. A score of at least 95 with timing error at or below 40 ms on tier 1 skips the middle probe and moves to the challenge; if both challenge attempts fail, the middle tier is offered as a fallback. The skipped tier remains explicitly untested. The fresh-pattern check uses an alternate groove; it is reported separately and never adds a demonstrated tier. The internal-pulse check plays the metronome for two bars and then drops it for two bars; it reports matched timing and drift without changing a tier. Every scored playing probe demonstrates one bar, counts four beats, and measures four bars. Only metronome clicks play during the measured phrase, except during the optional dropout check. Assessment input does not add ordinary practice sessions, personal bests or lesson completions. Saved result records stay at format version 1 and also record the shared content revision used. New fields are optional so older results and backups remain readable; legacy results with no revision are excluded from revision-to-revision comparisons and exported as unknown.

Advance a tier with a score of at least 85 and mean absolute matched-hit error no greater than 60 ms. Existing Great/Good matching windows and extra-hit penalties apply. A failed tier permits one retry; a second failure ends that domain. Skipping ends the current domain without treating higher tiers as failures. Stopping early retains only completed tasks.

Hands-only moves kick targets to tom to keep simultaneous voices distinct. Single-voice omits coordination. Keyboard/touch voice coordination is not evidence of physical limb independence. Adapted results carry their path label and are not compared with full-kit results.

MIDI dynamics measures alternating soft/accented snare strokes, requiring at least 80% matched targets and median accented velocity at least 20 above median soft velocity. At least two velocities in each target class are required; missing or constant velocity reports **Unmeasured**. Native MIDI preserves decoded velocity through an additive callback; existing MIDI clients retain their original callback.

Learners select a goal (balanced foundation, playing with others, reading notation or expressive playing) and a visual or audio-only question format. New assessments prioritize unseen questions; choices are shuffled, audio can be replayed, and answers appear in results. Learners can optionally report whether each assessed skill felt easy, about right, hard, or affected by input trouble. This feedback is saved separately and never changes scores or tiers. Larger notation and optional spoken or haptic count-ins can be enabled before starting. Setup guides learners through each required voice, plays its preview, and requires them to confirm the expected sounds match the labels before beginning; MIDI mapping can be reviewed before the check. MIDI setup also reports observed velocity range. Single-voice mode is described as one-hand friendly: it checks pulse and subdivisions on one voice and omits coordination; it does not imply physical independence. Results describe evidence confidence as not tested, limited, tentative or supported; this is an explanatory guide, not a statistical guarantee. Measurement-quality notes call out incomplete coverage, low hit matching, cutoff-near results, retries, and large saved timing corrections. Close scores can be checked with one alternate pattern; this evidence remains separate and never changes tier placement. Focused practice tips use misses, extra hits, timing spread and early/late bias. Results include a 60-second practice prescription and launch Trainer at its recommended tempo. Retry probes use a second versioned pattern where the skill allows an equivalent variation. Learners can return for the fresh-pattern check; retakes compare transfer, tempo and internal-pulse results when both are available. The bank and thresholds remain product defaults pending educator validation; they are not standardized placement norms. See [the educator pilot guide](ASSESSMENT_PILOT.md).

Backgrounding, input disconnection and audio interruptions discard the active probe without saving partial evidence. Completed tasks are checkpointed by web learner profile and on native device for 14 days; resume starts the interrupted task with a fresh demonstration and count-in. Completing or retaking clears the checkpoint. Changing the web learner resets the flow and loads only that learner's checkpoint. Input selection stays fixed within an assessment.

## Results and practice

Results show demonstrated tiers, a coverage-aware reading estimate, matched percentage, score, misses, extras, mean absolute timing error, early/late bias, timing spread, dynamics availability, quiz feedback and untested tasks. Audio-only results mark reading as untested; incomplete notation answers report coverage without assigning a reading tier. Comparable history shows tier, match rate and timing error. Recommendations follow the earliest observed unmet prerequisite and explain the evidence with a measurable next goal; omitted domains are not assigned invented scores. With no completed tasks, **Use this starting plan** is unavailable. Optional educator mode collects independent skill estimates before the learner starts, then offers fields for recommendation fit and disagreement notes after results appear. An optional teacher-assigned random code can link anonymous retakes; it must not contain identifying information. Exports omit the learner name, result date, and MIDI device ID. The offline pilot summarizer groups by content revision, input, and adaptation; reports educator agreement, learner input-issue feedback, retake consistency and item-level answer patterns with sample sizes and descriptive Wilson intervals.

Applying a result changes Home's suggested lesson and daily focus without completing lessons. Curriculum-matched practice targets are included in the shared content. Newer, reliable Trainer evidence on the same input profile, timing calibration and adaptation takes precedence for daily focus. Older native rounds lack comparison metadata and are deliberately excluded. Retaking leaves the applied plan intact until a result is explicitly applied.

The **Practice this skill** link carries only the random assessment record ID, then reads the result from the active learner's local storage. Web assessment results and Trainer report readiness after three consecutive reliable scored rounds on the recommended pattern with at least 85 score, 85% matched hits, and no more than 60 ms mean timing error, using the same input profile and adaptation. Native results and Trainer report three consecutive same-pattern scored rounds at 85 score and matched-hit percentage; native Trainer history does not yet persist hit timing offsets, so that readiness signal omits timing. This is practice feedback, not a replacement placement score. Retaking still does not change the applied plan until the learner applies the new result.

Web results are stored under the learner-scoped `drum-hero:assessment:v1` key and resume checkpoints under `drum-hero:assessment-draft:v1`. Native results use `drumHero.assessment.v1` and checkpoints use `drumHero.assessment.draft.v1`. Retain at most 20 completed records; when necessary, preserve the explicitly applied baseline and the newest 19 retakes. History supports review, deletion and stopping use of the plan. Deleting the applied result removes its plan reference. Native MIDI corrections are saved per Core MIDI source ID, with the previous shared MIDI correction used as the initial fallback for uncalibrated sources.

Web full backups already carry learner-scoped app settings, including assessments. Native v2 backups add an optional assessment field; older backups without it preserve the current assessment history. Native Trainer records add optional input/adaptation comparison metadata. Tempo results and educator comparisons are optional fields, preserving compatibility with older assessment records. Cloud sync and web/native backup conversion are not provided for assessment results.

The web `/assessment` route is included in the offline resource manifest; refresh an existing offline download after deployment. Native content and sounds are bundled. New web copy uses the existing translation fallback and native copy follows SwiftUI localization conventions; translations of all new assessment copy still require language review.

## Verification and remaining device work

`shared/assessment-fixtures-v1.json` pins identical TypeScript/Swift scoring cases for timing boundaries, missing/extra hits, negative offsets and velocity contrast. Unit tests cover advancement, skips, validation, recommendations, history retention and backup compatibility. Browser tests cover desktop/mobile layouts, accessibility, keyboard scoring, MIDI loss, profile isolation, applying a plan and interruptions. Native tests cover scoring parity, backup compatibility and simulator assessment flows.

Before a hardware release, manually check USB/Bluetooth MIDI on physical web/iOS devices, saved timing corrections, varied versus constant MIDI velocity, audio route interruptions, external keyboards, VoiceOver and screen-reader timing cues. Check iPhone/iPad layouts with larger text. Simulator and synthetic MIDI checks do not establish physical device latency or educator validity.

### Assessment extension status (2026-10-25)

Content revision 6 adds the expanded question bank and a separately scored 60–90 BPM pulse check. Web and iOS include educator pre-estimates and post-result lesson-fit notes, larger notation, and same-setup progress history. Automated tests and builds were not run for this extension. Newly added questions need educator review, and the pilot guide still needs real teacher/learner data before any thresholds or placement claims can be treated as validated.

### Assessment quality improvements (2026-10-26)

Web and iOS setup now checks each required voice and reports observed MIDI velocity range; changing the selected MIDI source clears the check so the new source must be verified. A larger versioned question bank reduces repeat exposure, and each result pins the selected question IDs. Optional spoken and haptic count-ins support access needs. Close probe results can receive one alternate-pattern confirmation, stored separately from tier placement. Results include match and timing trends plus a concrete 60-second practice prescription that respects the selected adaptation. Educators can pair anonymous retakes with a non-identifying code, and the local pilot summarizer reports repeatability without printing that code. Automated verification was not run for this extension. Live educator review and participant data collection remain necessary before changing assessment thresholds or making placement claims.

### Assessment quality follow-up (2026-10-26)

Content revision 7 adds one notation question to visual assessments and retains four listening questions for audio-only assessments; older four-question results remain readable and revision-specific comparisons keep them separate. Both platforms collect optional per-domain learner feedback without using it in the objective score, and require an explicit preview-to-label confirmation after the input voice check. Pilot summaries now include sample counts and descriptive Wilson intervals for educator agreement, lesson fit, item correctness and retake consistency. Web/iOS hardware comparability, screen-reader use, switch access and large-text layouts still require real-device and learner review. Automated verification was not run for these changes; no new pilot participant data was collected.
