# Trainer device validation

Drum Hero records a latency correction per Trainer input profile and provides an in-app compatibility summary. Browser feature detection and eight-beat calibration describe the current device; neither one certifies that a device has stable timing. The Trainer's **Record repeatability trials** panel can save three corrections for the same input profile, setup label, browser/platform version, and output route, then report their spread. Exporting creates a local JSON log after a review checkbox; entries are not uploaded. Individual MIDI device IDs are removed from the exported log. The setup label is user-entered and can contain identifying details, so review it before sharing. The comparison is a practical aid, not a calibrated laboratory measurement.

After explicitly exporting trial logs, combine and summarize them locally with `npm run device-validation:summary -- ./device-log-1.json ./device-log-2.json`. The summary groups matching browser, platform, input profile, setup label and output route, reports consecutive three-trial correction spreads, and omits the user-entered setup labels and trial IDs. Inspect the original files and physical setup notes before comparing groups; the summary is descriptive evidence, not device certification.

## Repeatable comparison procedure

1. Record the device model, OS version, browser version, input path, output path, and whether a wired or Bluetooth device is involved. Enter a short setup label in the Trainer trial panel.
2. Run the eight-beat calibration three times without changing the setup. After each calibration, save a trial, then note or export the reported correction spread.
3. Play the same 16-bar groove at one fixed tempo for three rounds. Keep the same input profile and do not compare microphone rounds with MIDI or touch rounds. In separate rounds, set random cues to every 1, 2, and 4 bars; verify the callout and scored response stay aligned when a one-bar groove repeats. Try voice-drop and accent-shift cues, then use a scored recap to start the one-minute focused drill and verify the selected voice, beat, tempo, and timer.
4. Repeat after reconnecting the input and after returning from a backgrounded tab. Confirm that saved profiles remain available and that a fresh calibration can replace them.
5. For microphone scoring, repeat in a quiet room and a normal practice room. Review noise, clipping, uncertain detections, per-voice calibration, and the recent per-profile input-quality history before interpreting score changes. Confirm flagged rounds lower the displayed reliability rate and that clean rounds raise it.
6. Repeat with Bluetooth audio only as a separate output configuration. Do not treat its result as comparable to wired audio.
7. In the iOS app, repeat with a wired USB MIDI kit and a Bluetooth MIDI kit. Confirm each voice and articulation maps from the displayed note, change one mapping and confirm it persists, then background the app and reconnect. For microphone scoring, select one voice, measure room noise while quiet, test soft and loud repeated strikes, and confirm that a sustained ringing tail does not repeatedly score while separate strikes still register. Check playback bleed with headphones. Export and restore a progress backup that includes personal songs; separately import a version 1 backup and confirm it leaves current personal songs intact. Export a learning archive on both platforms, merge it on the other platform, and verify lesson/session counts, tempo, guided session and weekly goal choices, song/groove duplicate handling, and unsupported-ID review. Schedule and turn off local practice reminders, then confirm they do not change cloud or archive data.
8. In the Android app, connect a USB MIDI kit, then use the Bluetooth scan flow for a Bluetooth MIDI kit. Confirm permission denial leaves touch practice available, and permission grant finds the kit. Confirm note 35/36 maps to kick, 37/38/39/40 to snare, 41/43/45/47/48/50 to tom, 42/44/46 to hi-hat, and 49/51/52/53/55/57/59 to crash. Run eight-click calibration three times, confirm the saved correction is per MIDI port, disconnect/reconnect and switch tabs, then play the same four-bar notation-led pattern at a fixed tempo. Export an archive, import it again, and verify supported progress merges while ear-training and Trainer details remain available for re-export. Android's current GM mapping and correction workflow are experimental until these physical checks pass.
9. In the Trainer, use the Easy start entry and confirm it selects the relaxed beginner setup. Build a custom song form from two grooves with different bar counts, repeats, and soft/strong section targets; add a fill after a section and score the complete form. Confirm all bars, dynamics targets, and transitions appear in the recap, then reload and confirm the form remains in the local groove library. Save a custom cue sequence, reload the page, and confirm its name and responses remain available on that browser profile.
10. Enable the scored Play-along challenge and try rock, funk, and shuffle. Confirm backing begins with the groove after count-in, follows tempo and repetition changes, stops on pause/reset, and resumes without a duplicate beat. Repeat with a microphone input and headphones to check backing bleed. Open the matching Play-Along Studio setup and verify its style and tempo are preselected.
11. Use keyboard-only navigation and a screen reader on the notation-led Practice Pad and Trainer, guided entry, skill-path controls, live cue response, custom cue editor, custom section controls, round explanation, backing controls, and the Play-Along challenge status. Confirm rests, beat counts, active targets, and the notation playhead are understandable; announcements remain useful and do not interrupt the metronome count or every rapid visual step.

This checklist is a release-validation plan. It does not claim that every listed physical device has been tested. Keep recordings and calibration results local unless a participant explicitly chooses to share them.

Record a release sign-off only after a person has run the matrix on the physical device. Include device model, OS and browser versions, input and output route, setup label, trial spread, observations, and reviewer. The app's diagnostics and repeatability log are local aids; a clean browser-capability check is not a hardware sign-off.
